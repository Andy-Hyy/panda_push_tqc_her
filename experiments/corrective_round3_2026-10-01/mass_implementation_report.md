# 第三轮 Phase C：质量实现

这一阶段使用 Phase B 已经通过的清洁 reset，线程仍是四项都设为 1，并且 `torch.set_num_threads(1)`。原 `push.xml` 和 `panda_mocap.xml` 的 SHA-256 在检查前后没有变化，分别仍是 `a5feb6af7c678b11254c05f1a41cf1bddd043b5c2fa93dfbb7c54171bce3f9cb` 和 `8c1608812335d02b2b0c7178bc1aae91351cf2c890d1633a2748b352e3d7dd09`。

四个写法事先固定。A 只改 `body_mass`，不缩放惯量，不调用 `mj_setConst`。B 改 `body_mass`，惯量留在编译出来的 1 kg 数值，然后 `mj_setConst`。C 把质量设为 m，惯量设为构造时那份惯量乘 m/m0，再 `mj_setConst`；乘数始终来自那份快照，不乘上一局已经改过的惯量。D 只在临时 XML 里改 `obj_geom` 的质量并重新编译，用来对照 C。正式主协议要的是 C 这种同形状、均匀密度的物体。

## 模型和短轨迹

质量 0.05、0.1、0.5、1.0 kg 上，C 和 D 的整模型字段都在预定容差内，最坏字段的最大绝对差是 0。物体惯量和 `body_invweight0` 逐项相同。0.05 kg 时两者都是惯量 `1.333333333333333e-05`、`invweight0` 为 `[20, 74999.99999999999]`。1 kg 时 A、B、C 都和 D 相同：惯量 `2.666666666666667e-4`，`invweight0` 为 `[1, 3750]`。默认质量下，`mj_setConst` 和惯量缩放没有把控制系统改成另一套。

A 在 0.05 kg 仍留着 1 kg 的惯量和 `[1, 3750]`。B 把平动 invweight 改成 20，转动 invweight 仍是 3750，因为惯量没有跟着质量缩小。`mj_setConst` 不会替你缩放 `body_inertia`。

短轨迹用 10 个事先固定的种子 `4200000` 到 `4200009`。每个质量先在默认模型上用清洁 reset 取出一套完整状态，再把这套 `qpos`、`qvel`、`act`、`ctrl`、mocap、时间和目标写进已经按该质量改好的 C 和 D，然后两边走同一条开环动作。动作由这套参考几何指向物体，20 步不变，不随某一种写法的观测重新采样。40 组里，C 和 D 的初始观测和 20 步 `qpos` 最大绝对差都是 0。

各自的原生 reset 是另一件事。同一个 `reset_seed` 下，手臂关节和物体的平面位置逐比特相同。物体高度最大差 `8.6e-8` m，`qvel` 最大差 `3.0e-6`。C 的清洁 reset 从时间 0 开始，D 用环境自己的历史 reset，时间是 setup 那一步留下的 0.5 s。D 在构造时就按编译质量做了那一步积分，所以 `initial_qvel` 和记录下来的物体高度可以和“先按 1 kg 构造、再在 reset 里改质量”的 C 差这么多。这个差别属于初始化，模型对照用的是上面那组被显式写成一样的状态。

## 50 个场景的 pilot

pilot 用 Stage 0 参数文件的前 50 行，episode 编号 0 到 49，`reset_seed = 4000000 + episode_id`。规则写在 `phaseC_scenes.csv`，没有用那 119 个不一致局来抽。每个场景比较 A、B、C，各做 mass-only 和四因素联合。延迟是真正的 0，用来把质量实现和动作延迟分开。三个策略各 300 行，惯量都停在该写法该有的数值上，没有累乘。

这是实现检查，不是论文里的成功率。分母是 50。

mass-only 成功次数：策略 0 是 A 47、B 49、C 49；策略 42 是 A 47、B 50、C 50；策略 123 是 A 47、B 50、C 49。四因素联合：策略 0 是 A 47、B 47、C 48；策略 42 是 A 42、B 48、C 47；策略 123 是 A 44、B 48、C 48。

成败不一致的次数，mass-only 上 A 对 C 是 4、3、4，B 对 C 是 2、0、1。联合条件上 A 对 C 是 5、7、8，B 对 C 是 3、5、4。步数不一致比成败多得多。mass-only 上 A 对 C 的步数不同有 25、26、26 局，B 对 C 有 5、6、7 局。联合条件上 A 对 C 是 27、32、28，B 对 C 是 16、20、13。B 比 A 更接近 C，但 B 的转动惯量没有随质量变化，步数仍然经常不同。

前 50 行里质量低于 0.5 kg 的场景是 7 个。三个策略、两个条件合在一起是 42 次比较，不是 42 个独立场景。这 42 次里 A 成功 26 次，C 成功 42 次。轻物体上，只改 `body_mass`、留下 1 kg 惯量的写法失败更多。质量不低于 0.5 kg 的 43 个场景、同样的 258 次比较里，A 成功 248 次，C 成功 249 次，成败不同 15 次，步数不同 137 次。质量已经不轻的时候，二进制成败常常还接近，轨迹长度并不接近。

因此 C 通过了和 XML 重编译的模型与短轨迹核对，可以作为下一阶段的质量实现。A 和 B 都留下了不同的动力学。pilot 的这些分数不能写进论文，也不能代替 600 局的 P1。

中间有一次三个进程同时编译环境时，MuJoCo 报告原始 mesh 路径暂时找不到。文件还在，续跑从已经写完的行接着做，三个策略最终都是 300 行唯一键。
